# 소득세법 RAG 데모

소득세법(법제처 원문 349개 조문) + 4대보험 + 법인세·부가가치세 핵심 조문 데이터를 기반으로,
월급 실수령액 계산과 세금 관련 자연어 질문에 답하는 RAG(검색 증강 생성) 데모입니다.

**아키텍처**: LangChain·벡터DB(FAISS/Chroma 등) 없이 순수 파이썬 + numpy로 직접 구현했습니다.
코퍼스가 357개 청크 규모라 `sentence-transformers`로 임베딩한 뒤 numpy 배열에 올려두고
코사인 유사도(`corpus_embeddings @ query_emb`)만 계산해도 충분히 빠릅니다. 검색은 임베딩
유사도 + 조문 제목 키워드 매칭을 섞은 하이브리드 방식이고, LLM 호출도 `google-genai` SDK를
직접 씁니다.

---

## 파일 구성

```
preprocessing.ipynb          ← 1단계: RAG 원본 데이터(DOCX) 만들기
income_tax_rag_demo.ipynb    ← 2단계: RAG 파이프라인 데모 (노트북)
app.py                       ← 2단계: 같은 파이프라인의 Streamlit 웹앱
data/소득세법_통합.docx       ← 위 둘이 공통으로 읽는 RAG 원본 (preprocessing.ipynb 산출물)
```

`preprocessing.ipynb`를 먼저 실행해 `data/소득세법_통합.docx`를 만들고, 그 다음
`income_tax_rag_demo.ipynb` 또는 `streamlit run app.py`로 실제 데모를 돌리는 구조입니다.

---

## 1. `preprocessing.ipynb` — 데이터 전처리

RAG가 검색할 원본 문서(`data/소득세법_통합.docx`) 하나를 만드는 노트북입니다.

1. **세법 보충 PDF 생성** — 소득세법 파일에는 없는 국민연금법·국민건강보험법·노인장기요양
   보험법·고용보험법·지방세법·법인세법(제55조 법인세율, 제19조 손금의 범위)·부가가치세법
   (제48조 예정신고와 납부, 제49조 확정신고와 납부) 총 9개 조문을 reportlab으로 PDF 생성.
   법인세법·부가가치세법 조문은 법제처 국가법령정보센터 원문 PDF를 직접 대조해 검증했습니다
   — 애초에 이 두 법이 코퍼스에 전혀 없어서 "부가가치세 신고 기한", "법인 비용 인정 기준"
   질문에 소득세법 조문이 잘못 검색되던 문제(검색 알고리즘이 아니라 데이터 누락이 원인)를
   여기서 해결합니다.
2. **소득세법 원문 적재·정제** — `data/소득세법.jsonl`(법제처 국가법령정보센터 원문, 349개
   조문)을 로드해 삭제된 조문 제외, 아직 시행되지 않은 개정 조문(중복 id) 제외 → 259개
   조문으로 정제.
3. **표 이미지 직접 검증 반영** — 원문 PDF에서 표가 이미지로만 렌더링돼 텍스트 자동추출이
   안 됐던 근로소득공제(제47조)·종합소득세율(제55조)·근로소득세액공제(제59조) 3개 조문은
   표 이미지를 직접 육안으로 대조해 복원한 값을 하드코딩. 이 검증 과정에서 근로소득세액공제
   한도 계산식의 실제 비율이 5%가 아니라 **1/2(50%)** 라는 실제 버그도 하나 발견해 바로잡음.
4. **DOCX 조립** — 위 내용을 하나의 `.docx`로 저장. 복원한 표 3개는 텍스트 나열이 아니라
   진짜 워드 표(Table)로 원래 위치에 삽입 — RAG 파이프라인이 곧바로 읽어들일 원본이라
   편집자 주석 없이 실제 법령 문서 형태를 그대로 유지.

## 2. `income_tax_rag_demo.ipynb` — RAG 파이프라인 데모 (노트북)

`data/소득세법_통합.docx` 하나를 읽어서 RAG 전체 과정을 단계별로 보여주는 교육용 노트북.
월급 3가지 예시(300/500/1000만원)를 순서대로 돌립니다.

| 단계 | 내용 |
|---|---|
| **인제스천** | `python-docx`의 `iter_inner_content()`로 문단·표를 문서 등장 순서 그대로 순회 → 조문 단위로 재구성 (표는 "구간: … / 공제액: …" 텍스트로 풀어써서 본문에 통합) |
| **청킹** | 항(①②③...) 단위로 분리 후, 너무 잘게 쪼개지지 않게 900자 이하로 재결합 |
| **검색(Retrieval)** | `ko-sroberta-multitask`로 임베딩 → 코사인 유사도 + 조제목 정확 일치 시 가중치 부스트(하이브리드) |
| **계산(Rule)** | 근로소득공제·종합소득세율·근로소득세액공제·4대보험료를 검증된 수치로 순수 코드 계산 (LLM 미사용, 환각 없음) |
| **생성(Generation)** | 계산 결과 + 검색된 조문을 Gemini 무료 API에 넘겨 근거 인용 자연어 설명 생성 (API 키 없으면 계산 결과+근거만 출력하는 폴백 모드) |

핵심 철학: **정확성이 중요한 부분(계산)은 코드에, 자연스러움이 중요한 부분(설명)은 LLM에**
맡긴다 — LLM이 세금을 계산하게 하지 않고 이미 계산된 결과를 설명하는 역할만 준다.

## 3. `app.py` — Streamlit 웹앱

같은 파이프라인을 자연어 질문 하나로 물어볼 수 있는 웹 UI로 감쌌습니다. `.env`의
`GEMINI_API_KEY`만 서버 쪽에서 읽고(프론트에 노출 안 함), 무거운 모델·임베딩은
`st.cache_resource`로 최초 1회만 로드합니다.

### 질문 자동 분기 (자연어 하나로 3가지 케이스 처리)

질문을 입력하면 아래 순서로 의도를 판별해서 다르게 처리합니다.

1. **"법인" + "사업자/개인"** 언급 → 개인사업자(종합소득세) vs 법인(법인세) 비교
   - 질문에 **금액이 있으면** → 그 금액 기준 1:1 비교
   - 질문에 **금액이 없으면**("얼마부터 유리해?") → 이진탐색으로 손익분기점을 직접 계산
     (교차가 한 번만 일어나는 걸 스캔으로 먼저 확인한 뒤 안전하게 이진탐색 적용)
   - 두 경우 모두 "법인 단계 세금만 비교한 것이며, 실제 인출(급여·배당) 시 세금이 추가로
     붙는다"는 경고를 항상 같이 표시
2. **"월급/연봉/실수령액" + 금액** → 실수령액 계산기
   - "연봉/연간/1년에/연에" 같은 표현이 있으면 12로 나눠 월급으로 환산, 없으면 월급으로 간주
3. **그 외** → 일반 RAG (상위 5개 청크 검색 후 근거 기반 자연어 답변)

금액 파싱(`parse_korean_amount`)은 "10억", "1억 5000만원", "3000만원", "5백만원",
"30,000,000원" 등 다양한 한글/숫자 표현을 인식합니다.

### 화면 구성 (답변 우선 순서)

라우팅 처리가 끝나면 아래 순서로 렌더링합니다(모두 `render_answer()` 공통 함수 사용):

1. 핵심 지표 카드 (예: 실수령액, 손익분기점) — 있을 때만
2. **AI 답변** — 번호 매긴 보고서체가 아니라 자연스러운 대화체로 결론부터 설명 (프롬프트에
   전용 말투 지침 삽입)
3. 계산 상세 표 — 접힌 expander (필요할 때만 펼쳐봄)
4. 근거 조문 — 접힌 expander. 각 조문마다 **검색 신뢰도를 코드가 직접 판단**해서 표시
   (✅ 조제목과 정확히 일치 / ✅ 유사도 0.6 이상 / 🟡 0.4~0.6 / ⚠️ 0.4 미만) — LLM의
   자기평가가 아니라 실제 유사도 수치 기반이라 신뢰할 수 있음

### 데이터가 없거나 Gemini 키가 없을 때

- Gemini 키 없음 → AI 설명 생략, 계산 결과·근거 조문만 표시 (앱은 정상 작동)
- 금액/의도를 못 찾음 → 다시 질문해 달라는 안내 표시

## 실행 방법

```bash
uv venv
uv pip install -r requirements.txt
source .venv/bin/activate

# 1) 최초 1회: RAG 원본 데이터 생성
jupyter nbconvert --to notebook --execute --inplace preprocessing.ipynb

# 2-a) 노트북으로 보기
jupyter notebook income_tax_rag_demo.ipynb

# 2-b) 또는 웹앱으로 보기
streamlit run app.py
```

`GEMINI_API_KEY`는 프로젝트 루트에 `.env` 파일을 만들어 설정합니다
(무료 발급: https://aistudio.google.com/apikey).

국세청 근로소득 간이세액표를 따르며 연말정산으로 최종 정산됩니다. 실제 세무 신고·상담은
